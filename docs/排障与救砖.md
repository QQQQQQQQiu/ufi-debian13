# 排障与救砖

## 0. 先接串口，否则下面一半内容你都做不了

随身 WiFi 没有屏幕，红灯/黑屏时唯一的线索就是串口日志。

- 拆机找板上的 **TX / RX / GND** 测试点，飞线到 USB-TTL 模块
- **UFI 系列是 3.3V 电平**（UZ801 是 1.8V，接错可能烧东西）
- 波特率 **115200**，8N1
- 内核 cmdline 里已带 `console=ttyMSM0,115200`，开机就能看到输出

没有串口，你只能靠「灯亮不亮」猜，效率极低。

## 1. 冷启动只有红灯，没有 USB、没有热点

**这是自编译固件最常见也最棘手的问题。** 社区有明确案例：boot/rootfs/aboot
分区回读校验全都一致，冷启动后依然只有红灯[citation:29]。

关键点：**写入校验成功只能证明存储层正确，证明不了
bootchain + kernel + DTB + firmware 这个组合适配你的板子。**

按顺序排查：

### 1.1 换 DTB（最常见的原因）

`config.env` 里改 `DTB_NAME`，或直接改 boot 分区里的
`/boot/extlinux/extlinux.conf` 的 `FDT` 行：

```bash
# 在设备上（或通过 9008 读回 boot 分区改）
sed -i 's|/dtbs/qcom/msm8916-thwc-ufi001c.dtb|/dtbs/qcom/msm8916-yiming-uz801v3.dtb|' \
    /boot/extlinux/extlinux.conf
```

`06-pack-images.sh` 已经把候选 DTB 全部打进 boot 分区，
并在 extlinux.conf 里放了一个 `debian13-fallback` 启动项，开机菜单可以直接选。

候选顺序建议：
`msm8916-thwc-ufi001c` → `msm8916-thwc-uf896` → `msm8916-yiming-uz801v3` → `msm8916-fy-mf800`

### 1.2 确认 lk2nd 是否认得你的板

lk2nd 是靠内置 DTB 的 compatible 串识别设备的。如果 UFI103S_V02 不在支持列表里，
lk2nd 可能直接拒绝启动。串口日志里会看到 lk2nd 的报错或设备名。

`config.env` 的 `LK2ND_DTB` 可以换（默认 `msm8916-512mb-mtp`）。

### 1.3 确认 moden/WiFi 固件放对了

UFI 板是闭源固件，缺了 WiFi 和基带都起不来：

```bash
ls /lib/firmware/ | head -30
# 应有 modem.mdt / modem.b0* / wcnss.mdt / wcnss.b0* / mba.mbn 等
dmesg | grep -iE "remoteproc|wcnss|mpss|firmware"
```

典型报错与含义：

| 报错 | 含义 |
|---|---|
| `unable to resolve mpss region` | DTB 缺 MPSS reserved-memory / memshare 节点，换 DTB |
| `modem firmware not found` | `/lib/firmware` 缺文件，从原厂备份的 `0.modem.fat` 里提取 |
| QMI 返回 `DeviceNotReady` | modem 固件版本与机器不匹配，别拿别的板子的固件顶 |

固件提取：用 7z 打开 9008 全盘备份里的 `0.modem.fat`（它本身是个 FAT 镜像），
把里面的文件全部拷到 `/lib/firmware/`，reboot。

### 1.4 回退

刷回 `01` 步备份的 boot 分区，或者整盘回写：

```bash
edl wf backup/orig_fw.bin
```

## 2. 超频没生效

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq
cat /sys/devices/system/cpu/cpu0/cpufreq/cpuinfo_max_freq
```

### 2.1 值还是 1209600

说明新 OPP 节点被挡住了。可能原因：

- **编译出的 DTB 没换上**：确认 `files/dtbs/qcom/` 下那个 dtb 确实是新编译的。
  用 `dtc -I dtb -O dts` 反编译出来搜索 `1401600000` 确认。
- **被 CPR / rpmpd 限制**：MSM8916 的 CPU 频率受 CPR 调压和 VDD_APC
  电源域共同制约。查看：
  ```bash
  dmesg | grep -iE "cpufreq|cpr|opp|rpmpd"
  ```
  若日志显示 OPP 被 fuse/speed-bin 裁剪，需要在内核里放宽限制，
  或改用 `cpufreq-dt` 而非 `qcom-cpufreq-nvmem`（见 `kernel-fragments/` 说明）。
- **governor 上限被锁**：`cpufreq-set -u 1401600` 手动抬一次试试。

### 2.2 高负载死机 / 重启

电压不够。逐步上调 `opp-microvolt`，每次 +25mV：

```bash
python3 tools/opp-overclock.py --apply --hz 1401600000 --microvolt 1225000 --dtsi <路径>
```

**不建议长期超过 1.3V。** 同时确认散热——28nm 芯片在密闭塑料壳里满载很容易过热。

### 2.3 想临时降回去

```bash
sudo cpufreq-set -u 1209600
# 或
echo 1209600 | sudo tee /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq
```

## 3. ADB 出不来

```bash
systemctl status ufi-usb-gadget adbd
ls /dev/usb-ffs/adb/        # 应有 ep0 ep1 ep2
cat /sys/class/udc/          # 应有 ci_hdrc.0 之类
dmesg | grep -iE "gadget|udc|ffs"
```

| 现象 | 原因 / 处理 |
|---|---|
| `/dev/usb-ffs/adb` 不存在 | 内核没开 `CONFIG_USB_FUNCTIONFS`，重新编译内核 |
| 有 ep0 但没 ep1/ep2 | adbd 没起来，看 `journalctl -u adbd` |
| 主机 `adb devices` 显示 unauthorized | 把本机 `~/.android/adbkey.pub` 内容追加到设备 `/root/.android/adb_keys` |
| 主机完全看不到设备 | UDC 没绑上，手动 `/usr/local/sbin/ufi-usb-gadget bind` |
| adbd 起来了但只监听 TCP | FunctionFS 不是以 `uid=2000,gid=2000` 挂载的，adbd 降权后打不开 ep0 |

重建一次：

```bash
sudo /usr/local/sbin/ufi-usb-gadget reset
sudo systemctl restart ufi-usb-gadget
sudo systemctl restart adbd
```

## 4. zram 起不来

```bash
zramctl          # 空 = 没起来
dmesg | grep -i zram
```

- `zramswap.service failed` → 内核没编 `CONFIG_ZRAM` / `CONFIG_ZSMALLOC`。
  这是很多现成底包的通病，本套件自己编译内核时已经打开，确认用的是本套件编译的内核。
- 模块形式的话要 `modprobe zram`，本套件直接编进内核（`=y`）。

## 5. 救砖

只要 9008 模式还能进，MSM8916 就基本不会真砖——这是高通方案相对展锐/ASR 最大的优势。

```bash
# 1. 进 9008：长按 RESET 插 USB，或短接 EDL 测试点
lsusb | grep -i 9008

# 2. 整盘回写（救砖）
edl wf backup/orig_fw.bin

# 3. 只回写射频校准（4G / IMEI 异常时用）
edl w fsc      backup/fsc.bin
edl w fsg      backup/fsg.bin
edl w modemst1 backup/modemst1.bin
edl w modemst2 backup/modemst2.bin
edl w persist  backup/persist.bin
edl w sec      backup/sec.bin

# 4. 重启
edl reset
```

**注意**：`fsc/fsg/modemst1/modemst2` 是本机唯一的射频校准数据，
绝不能用别的机器的文件顶替，也不要上传给任何人。

## 6. 其它常见问题

**文件系统变只读**
多次异常掉电后常见：
```bash
dmesg | grep -i "readonly"
sudo e2fsck -y /dev/mmcblk0pXX    # 先 df 确认根分区实际设备号
sudo reboot
```

**WiFi 热点搜不到**
```bash
nmcli device wifi list
nmcli connection up WiFi-AP
journalctl -u NetworkManager | tail -30
```
确认 `wcn36xx` 模块加载了：`lsmod | grep wcn`。

**4G 上不了网**
```bash
sudo systemctl start ModemManager      # ondemand 模式下默认没开
mmcli -L                               # 看到 modem
mmcli -m 0                             # 看状态
```
ModemManager 和 VoCat 这类短信工具会抢同一组 AT/QMI 端口，**只能二选一**。

**想重新打包/重来**
```bash
rm -rf rootfs build/files && ./scripts/05-build-rootfs.sh && ./scripts/06-pack-images.sh
```
